# Methodology

This document explains the methodological choices that make ClickRank a faithful model of ad ranking rather than a generic classifier benchmark. The first is the temporal split. The second is the choice of normalized entropy and group AUC as headline metrics over raw AUC. The third is the design of the synthetic data, which is built so that interaction aware models can beat a linear baseline for the right reasons. The last section documents the real Criteo run that produces the headline numbers in the README.

All randomness in the project is seeded with seed 42 so every result is reproducible.

## Temporal Split

The Criteo dataset is ordered by time, and ad data in general arrives as a stream. ClickRank splits by position with no shuffle. Train is the first 80 percent of rows, validation is the next 10 percent, and test is the last 10 percent. Each split has its index reset so downstream code sees clean contiguous frames.

The reason is data leakage. A random split mixes rows from across the whole time range into all three sets. The model then trains on impressions that occurred after some test impressions, which is information it would never have at serving time. Categorical vocabularies, frequency encodings, and any learned statistics would absorb future information, and the test metrics would be optimistic in a way that never holds once the model is deployed and always predicts forward.

A temporal split removes that leak. The feature pipeline is fit on train only. Frequency encodings, the rare token cutoff, the standardization statistics, and the choice of which columns to cross are all computed from the train split and then applied unchanged to validation and test. A category that appears only in the future gets a frequency of zero or collapses to the rare token, exactly as it would for a fresh impression in production. This is the cost of honesty. Metrics are lower than a random split would report, but they reflect real forward looking performance.

The split also matters for early stopping. Validation comes from a later time window than train, so stopping on validation logloss approximates stopping on near future performance rather than on a random slice of the same period.

## Why Normalized Entropy and GAUC Matter More Than Raw AUC

Raw AUC is the area under the ROC curve over the whole test set. It is a fine first look at ranking quality, but it answers a narrow question. It asks whether a random clicked impression scores higher than a random non clicked impression across the entire population. Two properties of ad systems make that question insufficient on its own.

First, ad systems need calibrated probabilities, and AUC is blind to calibration. AUC depends only on the ordering of predictions, not their absolute values. A model that outputs the right ranking but doubles every probability has the same AUC and is useless for pricing. Bids and pacing decisions multiply the predicted click probability by a value, so a systematic bias in the probability flows straight into mispriced auctions and overspent or underspent budgets. Normalized entropy and logloss are sensitive to the actual probability values, so they catch this where AUC cannot.

Normalized entropy is logloss divided by the entropy of the base click rate. The base rate is the mean of the labels, and its entropy is the logloss you would get by always predicting that base rate. Dividing by it makes the metric robust to the overall click rate of the traffic. A value below 1 means the model is more informative than the constant base rate predictor, and smaller is better. Because it factors out the base rate, normalized entropy is comparable across traffic segments and across time, which is why it is the standard reporting metric in the ad CTR literature. Relative improvement is the same idea expressed as a fractional reduction in cross entropy against the base rate, which gives an intuitive percentage style improvement number.

Second, an ad auction ranks ads inside a single user request, not across the whole population. The decision the system makes is which ad to show this user right now, chosen from the small set of ads competing for this one impression opportunity. Raw AUC pools all impressions together and can look strong even when within request ordering is weak, because it gets credit for separating easy cross population cases that the auction never actually has to decide. Group AUC fixes this. It computes AUC inside each impression group and averages the per group values weighted by impressions, so it measures exactly the within request ranking that the auction depends on. In real systems the group key is a user id or a query id. ClickRank synthesizes impression groups for the test set by hashing a categorical column into a number of groups so GAUC is computable offline, and the documentation is explicit that production groups are user or query ids.

Put together, the headline read on a model is normalized entropy and GAUC, with raw AUC and logloss as supporting context and calibration curves as the visual check. A model that wins on raw AUC but loses on GAUC or calibration is the wrong choice for an auction, and these metrics surface that.

## Synthetic Data Design

ClickRank ships a synthetic generator so it runs end to end with no downloads. The generator is not a throwaway. It is designed so that the model comparison is meaningful, which means interaction aware models must be able to beat a linear baseline for a reason that reflects real ad data.

The schema matches Criteo exactly. There is one binary label, 13 dense numerical columns named I1 through I13, and 26 sparse categorical columns named C1 through C26. Numerical columns are drawn from heavy tailed lognormal and pareto distributions to mimic the long right tail of real impression and count features, and about 10 percent missing values are injected into a few of them so the is_missing indicator has real variation to learn from. Categorical columns are hex like strings with a spread of cardinalities, from high cardinality fields near 5000 down to low cardinality fields near 10.

The label is the part that makes the benchmark work. Each categorical value carries a hidden integer group id that the model never sees directly. The latent logit that drives the Bernoulli click label is built from three kinds of structure. The first is linear effects, where a few numerical features and a couple of categorical group memberships contribute additively. A linear model can fit these. The second is pairwise interactions, where the logit rises sharply when the hidden group of C1 matches the hidden group of C2, and again when the hidden group of C3 matches the hidden group of C4. These match terms are pure second order effects. A linear model cannot represent them from the raw frequency or one hot features, because the effect depends on the conjunction of two values rather than either one alone. The interaction coefficients are deliberately large so the gap they create is visible in the metrics. The third is a smooth numeric effect from log transformed dense features plus gaussian noise so the task is not trivially separable.

This design is what lets the factorization machine family and the deep cross network earn their lead. FM models the pairwise interactions directly through low rank embeddings. DeepFM and DCN add deep towers and an explicit cross network on top. The plain DNN can approximate the interactions implicitly. The logistic regression baseline can only fit the linear part, so it is expected to trail. The intercept is tuned so the base click through rate lands roughly in the 0.2 to 0.3 band, which is a realistic range for the benchmark and keeps both classes well represented. The whole generator is deterministic given the seed, so the synthetic benchmark is as reproducible as a fixed dataset would be.

To swap in real Criteo data, place a TSV or CSV at the data path and the loader will read it with the same schema and the same temporal split. The methodology above applies unchanged, since the synthetic generator was built to share the structure that makes the real data interesting.

## Real Criteo Data

The headline results in the README are produced on the real Criteo Display Advertising Challenge dataset, not on the synthetic generator. The data is fetched by `scripts/download_data.sh`, which streams a public figshare mirror of dac.tar.gz and extracts only the first N rows of the labeled train.txt. The stream is piped through head, which closes the pipe once N rows are read and stops the download early, so a 2 million row sample costs about 1 GB of transfer rather than the full 11 GB extracted file. The loader reads only the requested number of rows from disk, which keeps memory bounded on the large file.

The real data confirms why the feature engineering matters. The true click rate is about 25 percent, since the Criteo training set subsamples negatives. The categorical fields are far higher cardinality than the synthetic ones, with several fields reaching into the hundreds of thousands of unique values even in a 2 million row sample and into the millions across the full set. This is why hash encoding is essential and one hot encoding is not an option. Numeric missingness is heavy and uneven, with some integer features missing in more than 70 percent of rows, which is exactly the case the is_missing indicators are built for.

On a 2 million row sample with a temporal split the ordering matches the synthetic story and the published literature. The factorization machine family and the deep models reach about 0.787 AUC while logistic regression reaches about 0.718, a lift of roughly 0.069 AUC and a normalized entropy drop from about 0.898 to 0.813. All models stay well calibrated with expected calibration error under 0.011. The absolute AUC sits a little below the best published Criteo numbers because this framework caps the hash space at 10000 buckets per field to keep the embedding tables and memory bounded, which trades a small amount of accuracy for a benchmark that runs on a laptop. The relative comparison, which is the point of the benchmark, holds clearly.
